A1 Research 2025 – 26

Diversity, Maximized

My research: a streaming algorithm that picks the k most spread-out points of a huge dataset in a single pass, ignores the outliers, and uses memory that doesn't grow with the data.

Paper · arXiv:2610.01456 Streaming algorithms for robust max-min diversification with A. Pietracaprina & G. Pucci · read on arXiv ↗

Imagine millions of items (documents, products, images) and room to show only ten. Which ten? You want them as different from each other as possible, so together they cover the whole range. Formally, that's max-min diversification: choose k points so that the smallest distance between any two of them is as large as possible.

The catch is that this objective is very sensitive to noise. A few isolated points look “very different” and get picked. A robust version of the problem excludes z outliers: the points whose nearest neighbour is farthest away. The previous streaming algorithm for it needed memory that grows with the data, could return fewer than k points, and only excluded outliers with some probability.

With Andrea Pietracaprina and Geppino Pucci, I designed a deterministic algorithm that reads the data once, as a stream, and always returns exactly k inliers, assuming inliers and outliers are reasonably well separated. Its solution is a (2+ε)-approximation, only ε above the best ratio achievable in polynomial time even when there are no outliers. It adapts automatically to the data's doubling dimension, and for wide ranges of parameters its memory doesn't depend on the size of the dataset.

Guarantee
Exactly k inliers · (2+ε)-approximation · deterministic
Resources
One pass · memory independent of n for wide parameter ranges

    Track A1 · Liner insert

    Choosing well, with outliers

    1. Set aside the outliers. The z points whose nearest neighbour is farthest away (red) are excluded, the same definition used in the paper. They look “different”, but they're just noise.
    2. Start at the edge. Pick the point farthest from the centre of the remaining data.
    3. Go farthest-first. Keep adding the point farthest from everything chosen so far, until you have k.

    The dashed circles never overlap. Their radius is half the smallest distance between two chosen points, and that distance is what we want to maximise.

    This is a simplified, offline teaching version. The algorithm in the paper reads the points once as a stream, keeps only a small coreset in memory, and is guaranteed to return exactly k inliers forming a (2+ε)-approximate solution.
